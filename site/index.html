    04

    What exists today

    The reference half of this page. Everything below is shipped, tested code you can run right now — seven crates, four devices, one interaction prototype. Nothing here is a plan.

    The application shell runs ./spectre

    A native egui interaction prototype (decision 8). It is a real UI over the real model — track state, device descriptors and parameter values are the backend's own, not mock data. Since R4-1 it also owns a real audio thread: on its first frame it compiles a plan from the app snapshot, opens the default device through the backend seam at its own native rate, and moves the render bridge into the callback. The transport bar reads ENGINE RUNNING only once a block has actually been rendered — an opened stream that has not called back reads ENGINE OPENED. What has not happened is a manual listening pass: no one has confirmed by ear that sound leaves the speakers.

    Four lenses over one project model, switched with keys 1–4:

    • Arrange — the timeline placeholder; shows the compiled stereo path and a Pulse Pattern clip strip.
    • Build — the native device signal path as cards. Every card offers Open in Shape, which atomically preserves track selection, focuses that device by its stable ObjectId, and switches lens. If the ID is invalid the whole transition rolls back — lens, selection, and device state together.
    • Shape — renders only the selected device, with controls generated from backend parameter descriptors: real ranges, real defaults, a Reset per parameter. Ordinary lens changes and parameter edits preserve device focus.
    • Mix — the master route placeholder.

    Keyboard: Space toggles play/stop, 1–4 select the lens. No shortcut map beyond that has been designed — the workflow research explicitly lists default keymaps among the conclusions its evidence cannot support, so none has been invented.

    Track list supports add, name, select, and per-track Mute / Solo / Level, and since R4-4 those edits reach the render thread: level, mute, and solo publish an effective gain on the parameter lane, while add, remove, and reorder mark the plan PLAN STALE and offer a rebuild rather than recompiling on the callback. The Arm toggle is a disabled button that says recording arrives at R7, because there is no recording path to arm for. Browser (Instruments, Effects, Modulators, Samples, Plugins) is present and deliberately disabled: "Catalog wiring arrives in later milestones."

    Clips exist in the model as of R4-5 — create, select, activate, and an accessible label carrying name, position, length, note count, and state — but no clip lane or inspector is drawn yet. The surface is model-only, and the drawing is R4-9's.

    App parameter edits can be transferred as an owned snapshot into deterministic offline rendering, independently of focus. The complete four-parameter fixture is validated — exact membership, no duplicates, no aliases, no unknown identities — before any value is allowed to construct a processor.

    Realtime contract enforced in CI RT-001 · RT-002 · RT-003

    The published discipline the whole engine is built around. All three are enforced by tests, not by convention.

    RT-001 — nothing on the callback. Callback-reachable code must not allocate, deallocate, take blocking locks, perform I/O, log, or panic across the callback boundary. A thread-local flag marks an RT section and the global allocator records any allocation inside one, so a violation is attributed to the exact call rather than inferred from before/after totals. A positive control deliberately allocates inside a guarded section and asserts the guard fires — which is what makes every passing result meaningful instead of a broken probe reporting success. Guarded: bridge render, both bridge refusal paths, control drain, retire, and the plan driven through a real backend callback.

    Lock-freedom is enforced structurally, by scanning the RT modules for Mutex, RwLock, Condvar, thread::sleep, and logging macros. This is labelled the weaker of the two guarantees: it proves those modules never name a blocking primitive, not that no future call could reach one indirectly.

    RT-002 — bounded, wait-free, reclaimed off-thread. Three lanes, per decision 21. Parameters are latest-wins per (device, parameter) target, so a 5,000-write knob sweep coalesces to one application and cannot starve anything. Notes and transport are strict FIFO and are never dropped to make room; overflow is a counted defect read off-thread, not silent loss. Retired render state travels back to the app thread on a reclaim lane, and when that lane is full the value is handed back rather than dropped — because dropping it on the audio thread would deallocate.

    RT-003 — denormals flushed, NaN contained. Containment runs on each node's output before it can reach any downstream device. Denormals flush to signed zero via a software FTZ-equivalent, chosen over CPU control-register manipulation because it is portable across macOS and Linux and needs no platform-specific unsafe code. Any NaN or infinity silences that entire node — not just the offending sample — and records it as the last contaminated node, so one poisoned sample cannot leak the rest of the block.

    spectre-core 67 tests identity · time · transport · events

    The musical kernel. Stable 64-bit ObjectIds with zero excluded and project-scoped uniqueness validation; creation sequence owns ordering.

    Explicit time types — SampleTime(i64) and fixed-point BeatTicks(i64) at 960 ticks per beat. Raw numeric time in APIs is prohibited and conversions are defined exactly once. The tempo map converts deterministic piecewise tempo over signed pre-roll and projects of at least 24 hours; segment durations accumulate with unrounded absolute anchors and round once, at integer-sample conversion. BeatTicks → samples → BeatTicks preserves the tick. The reverse direction claims only what is true: arbitrary samples → BeatTicks → samples selects the nearest tick within half a local samples-per-tick plus half a sample — not an impossible exact round trip.

    Bounded event ordering. Musical ranges are half-open [start, end), and events at identical sample offsets carry a total deterministic order: transport, note-off, note-on, CC, parameter. Time signatures carry numerator 1–99 and denominator in {1, 2, 4, 8, 16} as a starting envelope with a Spectre rationale — an adopted envelope, not a copied one.

    Parameter descriptors carry stable identity, typed range, default, display mapping, and unit. Normalized value semantics are defined once, here.

    spectre-dsp — the six shipped devices 38 tests ToneSource · PulseInstrument · Gain · Saturator · Filament · Gloam

    The planar-buffer processing contract, bounded note events, and Spectre's original v1 device set. All six satisfy the Send bound the callback bridge requires, and none of them trips RT-003 containment during ordinary rendering.

    • ToneSource — a deterministic tone generator; the reference source for offline equivalence fixtures.
    • PulseInstrument — the note-driven source. Takes bounded note events and is the instrument end of the R4 fixture.
    • Gain — a single clamped f32 with an instantaneous setter. The accepted architecture document asserts twice that Gain smooths; the shipped Gain holds no smoothing state. That conflict is open as decision D-R3 and is deliberately unresolved by any agent.
    • Saturator — drive and mix; the effect end of the fixture.
    • Filament R4-6 — the alpha's own voice. One monophonic oscillator whose lean control moves the breakpoint of a phase map, behind a linear amplitude contour. At the default lean of 0.5 the map is the identity and the output is a bit-exact sine, which is what the default is derived from rather than chosen.
    • Gloam R4-6 — one pole per channel, whose corner opens with the signal's own magnitude follower. First order deliberately: one pole is the highest order whose stability needs no argument beyond "the coefficient is in [0, 1]", and a second would introduce resonance, and resonance introduces a Q limit with nothing behind it.
    • SumBus R4-4 — the mix point. Accumulates in f64 and rounds once at the store. No limiter, no clip, no normalization: summing sixteen tracks can exceed unity and R4 lets it.

    Since R4-2 every device answers a required set_parameter on the process trait — required rather than defaulted, so a device added later must answer the seam instead of silently ignoring every edit made to it.

    spectre-graph 21 tests EditableGraph → CompiledPlan

    The GRAPH-001 split, and it is a type-level split rather than a convention: the editable graph and the immutable compiled render plan are distinct types, and the callback executes only compiled plans. Compilation validates and allocates; execution does neither.

    Implicit cycles fail validation with a diagnostic. Explicit priced feedback edges — one render-quantum delay — are designed but gated at decision 7 until R11, so GRAPH-002 is honestly still proposed rather than implemented.

    RT-003 containment lives inside CompiledPlan::process and accumulates as plain integers on the render path, keeping this crate free of atomics; the audio bridge republishes those counts into its own telemetry atomics each block so the app thread can read them without a lock.

    spectre-audio 98 tests · wired backend seam · transport · bridge · MIDI · clips · telemetry

    The complete live shell R3 delivered, and since R4-1 the thing ./spectre actually launches. It is the largest tested crate in the workspace.

    Backend seam (decision 19). AudioBackend owns device enumeration and stream construction; AudioStream owns the Stopped/Running/Closed lifecycle. StreamConfig validates sample rate, channel count, and buffer size against explicit inclusive bounds before any driver call, so an invalid open fails before it reaches cpal. CpalBackend is the only file where cpal types appear and sits behind a default-on feature; NullBackend drives its callback through an explicit pump rather than a timer, so tests observe exact block counts with no sleeps, no races, and no hardware.

    RenderBridge. Drains transport commands and notes, executes the existing compiled plan, and interleaves stereo output into the driver buffer. There is no second render path — and that is proven, not asserted: the test rebuilds the offline fixture exactly, drives it through the bridge, and hashes the interleaved output with the same FNV-1a walk the offline harness applies to its planar output. The hashes match, and the fixture's peak is nonzero, so the match is not two silent buffers agreeing. Oversized blocks are refused into exact silence rather than stale audio.

    MIDI ingress. Absolute sample timestamps become block-relative frame offsets. A message past the end of the block is refused so it can be delivered with its own block; a message timestamped before the block is late, not invalid, so it clamps to the block start and is counted rather than discarded. MIDI carries no note identity, so ingress allocates a nonzero ID per attack and matches the release from a fixed 16×128 table — which is also what makes all-notes-off coherent.

    Health telemetry. Fractional headroom per block published as f32 bits in an atomic, with the worst case tracked. Worst-case headroom starts at infinity so the first block establishes the real minimum — a zero default would have looked indistinguishable from a saturated callback.

    Clip playback and the merge rule R4-5 · 43 tests bake · schedule · player · one sort

    A clip is a repeatable phrase written once. It is the smallest object that turns a signal chain into a sequencer, and R4's exit list contains exactly one clip row.

    Two domains, one conversion. Clips live in the musical tick domain on the track model — MidiClip holds notes, ClipPlacement puts one on a timeline, TrackClips keeps a track's placements ordered and non-overlapping. ClipSchedule::bake resolves them to absolute sample positions through TempoMap::ticks_to_samples and nowhere else, so no second time conversion exists to drift from the first.

    Non-overlapping is an invariant, not a preference. Every R4 instrument is monophonic — a second attack replaces the first — so overlapping placements would produce a defined but musically wrong result. Supporting them properly needs polyphony, which is a later milestone's decision. Refusing the overlap keeps the model honest about what the engine can actually do.

    The merge rule is the feature. Two producers now feed one note node, and the bridge used to push lane events without sorting — correct only because the MIDI ingress sorted before its events entered the lane. Adding a second producer breaks that in two independent ways: interleaving, and key collision, since the plan's validator rejects order <= previous and equality is a rejection rather than a tie. So clip and lane events are collected into one array and sorted once, by the same tuple the validator checks. contract_order is that key's single definition and both the player and the bridge call it; there is no second rank function and no second sort key.

    Sequence uniqueness is by band, not by renumbering. Clips take 1 << 63 upward; ingress numbers from zero. The bands cannot meet — reaching bit 63 would take 2⁶³ admitted messages, about 292,000 years at a sustained million per second. The user-visible consequence is deliberate: at an identical frame offset and identical rank, a live-performance event resolves before a clip event. The thing the player just did wins the tie.

    Two limits stated rather than hidden. The 512-event per-block reserve clears the densest monophonic block Spectre's own tempo and tick bounds admit, with 2.5× margin — but it does not bound polyphony, because notes stacked on one tick are representable. Density is bounded by counted refusal into an all-notes-off, never by a partial event set that could leave a hung note. And the two-segment loop bound is stated against the granted block, a driver property, with the condition that would require rederiving it written into the ledger row.

    A bridge with no clip player behaves exactly as before, and that is load-bearing. R4-1's evidence pins that a Play and a Stop landing in one block are refused into counted silence, and the refusal comes from the lane's own order. Sorting that pair would put the all-notes-off before the note-on by rank and leave the note sounding after Stop — a stuck note where there was a clean refusal.

    08

    Reference research

    Spectre is designed against a clean-room corpus of publicly authorized sources. Every claim is layered — OBSERVED for what a source states, SOURCE-GAP for what it does not, SPECTRE-CANDIDATE for a Spectre idea it suggests — so no product behaviour can quietly become a Spectre requirement.

    Quarantined

    The Serum 2 corpus — 250 records, the largest single extraction — is held out of use. It claims a 354-page official user guide as its primary source, but no source ledger records were written for that guide, so its provenance cannot be checked. Nine R4 specs respected the quarantine; one found the single convenient record it wanted and refused it in writing. Resolving this is decision D-R2.
