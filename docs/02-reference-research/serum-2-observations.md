# Part 1 — Official-source observations

## 1.1 Product identity and version anchors

- `OBS-SR2-VER-001` `OBSERVED` (UG p.1, title page): The official user guide identifies itself as documenting product "Version 2.0.18", manual version "1.0.3", dated April 27, 2025. It states Serum 2 is a synthesizer instrument plug-in for VST3, Audio Unit, and AAX hosts on Microsoft Windows and Apple macOS. The guide is 354 pages.
- `OBS-SR2-VER-002` `OBSERVED` (WN p.1, title page): The official change guide identifies product "Version 2.0", manual version "1.0.0", dated March 17, 2025, across 20 pages. It names the same three plug-in formats and the same two operating systems.
- `OBS-SR2-VER-003` `OBSERVED` (PROD, specs/system requirements/demo blocks): The product page advertises VST3, AU, and AAX 64-bit; Windows 10 or newer; macOS High Sierra or later on Intel and Big Sur or later on Apple Silicon; a 64-bit VST3/AU/AAX-compatible host; 626+ included presets and 288 included wavetables; and a downloadable demo limited to 15 minutes of use. The demo download was labelled build 2.1.5 for both platforms on the access date.
- `OBS-SR2-VER-004` `OBSERVED` (UG p.322, "Checking the Build Version and Date"): The running build version and its date are displayed in the Xfer pane of the GLOBAL page, and the guide instructs users to cite that number when contacting support. The guide therefore documents a user-visible build identity distinct from the manual version.
- `OBS-SR2-VER-005` `OBSERVED` (UG p.1; WN p.1): Both official documents carry the same copyright reservation forbidding reproduction or transmission of any part of the document without written consent. All records in this file are paraphrase, never transcription.

## 1.2 Voicing, polyphony, and voice stealing

- `OBS-SR2-VOICE-001` `OBSERVED` (UG p.216, "Mono"): The MONO switch limits the instrument to one active note. A new note pressed while one is sounding interrupts the earlier note; the guide describes the mechanism as re-pitching the existing note rather than starting a new one.
- `OBS-SR2-VOICE-002` `OBSERVED` (UG p.216, "Legato"): LEGATO is only audible with MONO enabled. When a monophonic voice is interrupted, LEGATO decides whether envelopes and LFOs retrigger; enabled means no retrigger and a smooth transition to the new pitch.
- `OBS-SR2-VOICE-003` `OBSERVED` (UG p.216, "Legato" callout): With LEGATO enabled and MONO off, the instrument behaves paraphonically, and the guide says this is most noticeable when ENV 2 modulates a filter. Envelope-retrigger control for effect assignments is exposed through the same switch.
- `OBS-SR2-VOICE-004` `OBSERVED` (UG p.185, "Inverting the Legato Setting"; p.216): An individual envelope can be inverted against the global LEGATO setting by right-clicking the envelope graph and choosing Legato Inverted, forcing that envelope to trigger at every note-on even when legato is enabled.
- `OBS-SR2-VOICE-005` `OBSERVED` (UG p.216, "Poly"): POLY sets the number of simultaneous notes and is disabled while MONO is enabled. The guide characterises eight voices as typically sufficient and sixteen as a lot, and gives long-release patches driven by arpeggios as the documented overload scenario. No maximum POLY value is stated.
- `OBS-SR2-VOICE-006` `OBSERVED` (UG p.216, "Polyphony Count"): A polyphony readout shows playing voices over allowed voices in the form `0 / 1`. The denominator is not the POLY setting alone; it totals the voices a patch has active, so enabling a second oscillator changes the display from `0 / 1` to `0 / 2`.
- `OBS-SR2-VOICE-007` `OBSERVED` (UG p.216, "Polyphony Count" callout): A single note's voice count includes its unison voices and, when an oscillator is in GRANULAR mode, its grain count. Voice accounting is therefore not one-voice-per-note.
- `OBS-SR2-VOICE-008` `OBSERVED` (UG p.217, "Limiting Polyphony"): Right-clicking the POLY field exposes `Limit Same Note Poly to 1`, which prevents a second sounding instance of an already-sounding note number. The guide names bass lines, monophonic synths, and drum kits as the intended use.
- `OBS-SR2-VOICE-009` `OBSERVED` (UG p.217, "Voice Steal Priority"): Right-clicking POLY exposes a Voice Steal Priority submenu whose options name the voices that are *preserved*. The published table is: Newest → terminate the earliest played note; Oldest → terminate the most recently played note; Highest → terminate the lowest-pitched note; Lowest → terminate the highest-pitched note; Velocity → terminate the note with the lowest input velocity. Five policies, one selectable at a time.
- `OBS-SR2-VOICE-010` `OBSERVED` (UG pp.217–218, "Portamento Settings"): Portamento exposes four controls. PORTA sets glide rate. CURVE sets the glide contour, with convex (the described typical setting) departing the source pitch quickly and decelerating into the destination, and concave (dragged below half) doing the reverse. ALWAYS makes portamento occur on a new note even when no note is currently held; disabled, a note must be held for portamento to apply to the following note. SCALED makes the glide time depend on interval distance: one octave uses the PORTA time exactly, smaller intervals glide faster, larger intervals progressively slower.
- `OBS-SR2-VOICE-011` `OBSERVED` (UG p.43, "Phase Legato"): Default wavetable-oscillator phase behavior is asymmetric with respect to legato. With LEGATO disabled and a voice stolen, oscillator phase does not reset at note-on. With LEGATO enabled and playback polyphonic (including when no voice is stolen), oscillator phase does reset at note-on. The guide states this matches Serum 1 and exists to avoid note-on clicks, and that the behavior can be toggled by right-clicking PHASE and choosing Phase Legato.

## 1.3 Oscillator common operations, pitch, and routing

- `OBS-SR2-OSC-001` `OBSERVED` (UG p.28, "Enabling an Oscillator or Filter"): An oscillator is enabled by clicking its label; the enable button turns green and a disabled oscillator dims its whole panel. Filters are enabled by clicking the power button directly rather than the label. The guide names muting an oscillator as both a soloing aid and a CPU-freeing action.
- `OBS-SR2-OSC-002` `OBSERVED` (UG p.29, "Choosing Oscillator or Filter Options"): Oscillator content and filter type are chosen from a drop-down; `<` `>` arrows step to the previous/next entry, and hovering the menu with the mouse wheel rotates through options.
- `OBS-SR2-OSC-003` `OBSERVED` (UG p.29, "Using Pitch Controls"): Oscillator pitch is split across four separate controls rather than one combined value: OCT (octave), SEM (semitone), FIN (fine, in cents), and CRS (coarse, continuous non-snapping semitones). The guide states the split exists specifically to make each independently automatable and modulatable, and names CRS as the destination for wide continuous sweeps.
- `OBS-SR2-OSC-004` `OBSERVED` (UG p.30, "Setting the Octave or Semitone Mode"): Right-clicking OCT or SEM selects among four pitch modes — Semitones (12-TET intervals), Harmonics (whole-number multiples of the base frequency), Ratio (pitch expressed as a ratio relative to a selected source, with a separate SRC selector), and Step (periods and steps as defined by the active MTS-ESP tuning). Step only appears when microtuning with an MTS-ESP source is available.
- `OBS-SR2-OSC-005` `OBSERVED` (UG p.31, "Routing an Oscillator or Filter"): Every oscillator (OSC A, OSC B, OSC C, SUB, NOISE) and both filters route to one of four targets: Filter (to FILTER 1, FILTER 2, or a continuous blend of both), Main (through the effects section), Direct (bypassing filter and effects, mixed with the main output), or None. The guide names None as the way to use an oscillator purely as a modulation source without contributing to the output.
- `OBS-SR2-OSC-006` `OBSERVED` (UG p.31, routing panel description): Default routing in a new preset is OSC A → FILTER 1, with FILTER 1 itself not enabled; all other oscillators and both filters default to the Main output.
- `OBS-SR2-OSC-007` `OBSERVED` (UG p.32, "Routing an Oscillator or Filter"): Independently of the four routing targets, a signal can also be sent to BUS 1 and BUS 2 via their own send knobs, making bus sends additive to the primary routing rather than an alternative to it.
- `OBS-SR2-OSC-008` `OBSERVED` (UG p.33, "Locking a Module"): Right-clicking a module label offers Lock Module, freezing that module's parameters across preset changes; individual controls inside a locked module can subsequently be unlocked. Choosing Init Preset from the main menu overrides this — it initialises everything and removes all module locks.
- `OBS-SR2-OSC-009` `OBSERVED` (UG p.34, "Initializing a Module"): Init Module returns one oscillator or filter to its initial state, including removing every modulator assigned to that module, without affecting any other setting.
- `OBS-SR2-OSC-010` `OBSERVED` (UG p.34, "Copying a Module"): Module copy/paste is two-tier. `Copy` transfers all settings except modulation assignments; `Copy (w/mods)` includes them. The copied configuration persists on an internal clipboard across preset changes and preset initialisation and can be pasted repeatedly. Copying a module between two separate Serum instances is explicitly not possible.
- `OBS-SR2-OSC-011` `OBSERVED` (UG p.34, "Copying a Module" callouts; p.349 Appendix G): Drag gestures on the module label mirror the menu: Option/Alt-drag copies without modulations, Shift-Option/Shift-Alt-drag copies with modulations, and dragging with no modifier **swaps** the two modules including their modulation assignments. Appendix G notes the same copy gestures also apply to oscillators on the MIXER page.
- `OBS-SR2-OSC-012` `OBSERVED` (UG p.35, "Enabling Pitch Tracking"): Pitch tracking is on by default and is toggled from the oscillator label context menu.
- `OBS-SR2-OSC-013` `OBSERVED` (UG p.35, "Enabling Pitch Tracking" callout): With pitch tracking disabled, the Multisample, Sample, Granular, and Spectral oscillators play C3 (stated as MIDI note 60), while the Wavetable oscillator plays C-2 (stated as MIDI note 0). The guide gives the wavetable case an explicit purpose: it allows a wavetable oscillator to be used as an LFO.
- `OBS-SR2-OSC-014` `OBSERVED` (UG p.36, "Pitch Bend Tracking"): A separate Pitch Bend Tracking toggle appears on the oscillator context menu only when pitch tracking is disabled, and only for Sample, Granular, and Spectral oscillators. It defaults to enabled. Wavetable and Multisample oscillators always track pitch bend when pitch tracking is disabled — that is, the option does not exist for them because the behavior is fixed.
- `OBS-SR2-OSC-015` `OBSERVED` (UG p.36, "Resizing the UI"): The window resizes by dragging the lower-right corner or by choosing a percentage from the Serum 2 logo menu; the current size can be stored as the default via a `Set x% as Default` entry, and `Default (100%)` restores it.

## 1.4 Wavetable anatomy, phase, unison, and warp

- `OBS-SR2-WT-001` `OBSERVED` (UG p.38, "Anatomy of a Serum Wavetable"): A Serum wavetable holds up to 256 subtables ("frames"), each a single-cycle wave, stored end-to-end in one parent file. One frame is audible at a time under normal conditions.
- `OBS-SR2-WT-002` `OBSERVED` (UG p.38, callout): On load, a frame is 2048 samples. The stated maximum file size follows as 2048 samples × 256 frames × 32 bits, which the guide states is exactly 2 megabytes.
- `OBS-SR2-WT-003` `OBSERVED` (UG p.38, callout): Interpolated frames are generated either by crossfading (mix blend) or by spectral morphing (frequency plus phase blend). They are computed at load time; the file embeds the interpolation type rather than the interpolated waveforms, which the guide gives as a disk-space measure. Persistence therefore stores an algorithm selector, not derived audio.
- `OBS-SR2-WT-004` `OBSERVED` (UG p.39, "Exploring the Waveform Display"): OSC A/B/C each offer a 2D and a 3D waveform view, toggled by clicking the waveform. 2D shows one frame and is the view in which warp effects are visible in real time; 3D shows all frames at once with the current frame yellow, stored frames green, and interpolated frames gray. The current frame number is displayed in the lower left.
- `OBS-SR2-WT-005` `OBSERVED` (UG p.41, "Phase"): PHASE sets where the oscillator starts playing at note trigger, described as the sample-start concept applied to a very short waveform. The guide names two conditions under which it is audible: a smooth waveform with a fast ENV 1 attack (a non-zero-crossing start clicks; it states 0% and 50% are the zero crossings of a default sine), and two or more oscillators with RAND off, where phase cancellation makes the relative start position change the tone.
- `OBS-SR2-WT-006` `OBSERVED` (UG p.42, "Randomizing the Phase"): RAND offsets PHASE by a random amount per new voice. Documented purposes are per-note attack variation, per-note tonal variation through varying inter-oscillator phase cancellation, and suppression of the unison "laser zap" sweep.
- `OBS-SR2-WT-007` `OBSERVED` (UG p.43, worked example): The guide gives a reproducible demonstration: PHASE 0 degrees, RAND 0 percent, UNISON 8, DETUNE lowered to roughly 0.10 produces an identical phasing sweep on every trigger, and raising RAND to 100% removes it entirely.
- `OBS-SR2-WT-008` `OBSERVED` (UG p.44, "Setting Phase Memory"): A phase-memory drop-down selects how phase and phase randomisation are determined for new notes, with exactly three options: All Voices (new notes use the PHASE and RAND settings; stated as the default), Contiguous (new notes continue the previous note's phase), and Per Voice (new notes start from the same editable phase each time). Switching to Per Voice while notes are sounding captures the current phase from the most recently sounded note.
- `OBS-SR2-WT-009` `OBSERVED` (UG p.45, "Wavetable Position"): WT POS selects the audible frame, with a documented minimum of 1 which selects the first frame. Right-clicking WT POS offers a smooth-interpolation option described as non-destructive — it smooths transitions between positions while leaving the wavetable intact.
- `OBS-SR2-WT-010` `OBSERVED` (UG p.45, "Unison"): UNISON stacks up to 16 voices per oscillator. The guide names 7 as the classic value and warns that higher counts sound cloudier. It states Serum compensates level as unison count rises so perceived volume stays constant, and that the UNISON field changes colour with the count as a CPU-cost reminder.
- `OBS-SR2-WT-011` `OBSERVED` (UG pp.46–47, "Unison" settings table): Unison MODE offers five detune distributions — Linear (even frequency spacing), Super (dense with slight stereo spread, named for supersaw), Exp (spacing widens exponentially away from centre), Inv (inverted, lower voices detuned more sharply), and Random (unpredictable per-voice detune).
- `OBS-SR2-WT-012` `OBSERVED` (UG p.47, "Unison" settings table): Unison STACK transposes rather than duplicates, with five options: Off, `12 (1-3x)` (original pitch plus octave transpositions spanning 1–3 octaves up), `12+7 (1-3x)` (original, fifth, and octave transpositions over the same span), `Center-12` (centre voices down one octave), and `Center-24` (centre voices down two octaves).
- `OBS-SR2-WT-013` `OBSERVED` (UG pp.47–48, "Unison" settings table): Per-voice unison spread is exposed for six further dimensions: WIDTH (stereo spread), RANGE (detune spread around the centre pitch), WT POS (per-voice wavetable frame, modulatable), WARP 1 and WARP 2 (spread of each warp amount around its knob position), plus DETUNE (tuning offset, applicable only above 1 voice).
- `OBS-SR2-WT-014` `OBSERVED` (UG p.48, "Unison Blend"): BLEND sets the level offset of the outer unison voices against the central voice — one central voice for odd unison counts, two for even. It is described as a wet/dry balance between the unison and non-unison sound, with a stated default of 75% described as an even blend across all voices, and it applies only when unison exceeds two voices.
- `OBS-SR2-WT-015` `OBSERVED` (UG p.49, "Warp"): Warp defaults to OFF. A warp mode is picked from a menu or stepped with `<` `>` arrows, and its depth is set by the adjacent knob. The guide states the 2D view shows warp effects for Sync, Alt Warp, and Distortion modes.
- `OBS-SR2-WT-016` `OBSERVED` (UG pp.50–56, warp-mode table): Warp modes are grouped into nine documented categories — Off; Sync; Alt Warp; Filter; Distortion; FM; PD; AM; RM — plus a `Swap Warps` command that exchanges the WARP 1 and WARP 2 mode assignments. Two warp slots exist per oscillator.
- `OBS-SR2-WT-017` `OBSERVED` (UG p.50, warp-mode table): Sync synchronises playback to an internal oscillator restarting in phase with the original. The warp control sets the internal oscillator's pitch, shifting harmonic content upward while the sounding pitch is retained; whole-number ratios (1:2, 1:5) are described as harmonious and other ratios as producing a saw-shaped cycle end. Selecting Sync reveals a WARP Var fader that moves the sync character from hard to soft.
- `OBS-SR2-WT-018` `OBSERVED` (UG pp.50–51, warp-mode table): The Alt Warp family has fifteen members: Bend +, Bend −, Bend +/−, PWM, Asym +, Asym −, Asym +/−, Flip, Mirror, Remap 1, Remap 2, Remap 3, Remap 4, Quantize, Odd/Even. Documented numeric anchors: Bend +/− treats 50% (12 o'clock) as no change; Remap 1 uses a drawn graph where a bottom-left to top-right diagonal is identity (y = x) and the warp knob scales from 0 (identity) to 100% (the drawn graph); Odd/Even yields the original signal at 50%, only odd harmonics at 0%, and only even harmonics at 100%.
- `OBS-SR2-WT-019` `OBSERVED` (UG p.51, warp-mode table): Remap variants differ only in how the same drawn graph is applied — Remap 2 applies it to each half of the waveform independently (mirrored), Remap 3 applies a sinusoidal remap, and Remap 4 applies the graph four times.
- `OBS-SR2-WT-020` `OBSERVED` (UG p.51, warp-mode table): Quantize is described as waveform-domain sample-rate reduction rather than an SR-reduction effect, with the documented consequence that the aliasing artefact tracks pitch instead of sitting at a fixed ringing frequency across all notes.
- `OBS-SR2-WT-021` `OBSERVED` (UG pp.51–54, warp-mode table): The Filter category has two members (LPF, HPF). The Distortion category has fourteen: Tube, Soft Clip, Hard Clip, Diode 1, Diode 2, Linear Fold, Sine Fold, Zero-Square, Asym, Rectify, Sine Shaper, Stomp Box, Tape Sat., Soft Sat.
- `OBS-SR2-WT-022` `OBSERVED` (UG pp.54–56, warp-mode table): The cross-modulation families each enumerate the same seven sources — the two other main oscillators, Noise, Sub, Filter 1, and Filter 2 — for FM, PD, AM, and RM. PD additionally offers PD (Self). Every one of these requires the source module to be enabled, though its output volume may be turned down so it acts purely as a modulator.
- `OBS-SR2-WT-023` `OBSERVED` (UG pp.54–55, warp-mode table): FM exposes three further options with distinct documented semantics. Thru-Zero inverts carrier phase and keeps oscillating when modulation drives carrier frequency below zero, instead of clamping at zero or reflecting. Exp uses an exponential scaling curve. Linear uses a proportional curve that preserves overall pitch under heavy modulation — and the guide states linear FM here is thru-zero but clamped at zero.
- `OBS-SR2-WT-024` `OBSERVED` (UG p.346, Appendix E "What Makes for a Good Wavetable?"): The guide's authoring guidance is that good wavetables are either many correlated frames or few frames, that frames should generally progress monotonically from dull to bright or the reverse so that WT POS travel is spectrally straight-line rather than zig-zag, and that thumbnails at the bottom of the editor can be dragged to reorder frames.
- `OBS-SR2-WT-025` `OBSERVED` (UG p.347, Appendix E "Interpolation"): Four un-interpolated frames automated across WT POS are described as producing four discrete tones with immediate jumps. `MORPH > Morph - Crossfade` in the Wavetable Editor is the documented remedy, and the guide notes that many other wavetable synths apply interpolation automatically to every preset table while Serum leaves it selectable.
- `OBS-SR2-WT-026` `OBSERVED` (UG p.347, Appendix E "Creating Wavetables from Scratch"): The drawing grid in the lower right determines snapping, and the guide names grid sizes 6 and 12 as bringing out the +7 and +19 harmonics. FFT bins can be drawn directly and right-clicked for further options including randomisation.

## 1.5 Envelopes

- `OBS-SR2-ENV-001` `OBSERVED` (UG p.183, "Using Envelopes"): There are exactly four envelope modulation sources, labelled ENV 1 through ENV 4.
- `OBS-SR2-ENV-002` `OBSERVED` (UG p.185, callout): ENV 1 is special: it is wired to the amplifier and controls each voice's output volume, and is described as always active. It may still be assigned to arbitrary parameters like any other envelope. When ENV 2, 3, or 4 is selected, ENV 1's shape remains faintly visible in gray behind it.
- `OBS-SR2-ENV-003` `OBSERVED` (UG p.186, envelope parameter table): The envelope model is five-stage — ATK, HOLD, DEC, SUS, REL — with HOLD sitting between attack peak and decay, and SUS being a level while the other four are times. Attack, decay, and release **curves** are editable only by direct mouse manipulation on the graph, not by knob.
- `OBS-SR2-ENV-004` `OBSERVED` (UG pp.184–185, "Configuring Envelopes"): The envelope display has a lock toggle. Locked, the envelope always zooms to fill the display and changing envelope times changes only the ruler scaling beneath it. Unlocked, the user drags in the zoom area below the lock button to zoom manually.
- `OBS-SR2-ENV-005` `OBSERVED` (UG p.185, "Setting Envelope Parameter Units"): An MS/BPM toggle switches envelope values between milliseconds and note subdivisions. Switching from MS to BPM makes Serum compute, per control, the note subdivision nearest the existing millisecond value using host tempo. The conversion is therefore lossy and one-way per switch.
- `OBS-SR2-ENV-006` `OBSERVED` (UG p.185, "Setting the Envelope Verticals"): The graph's background vertical lines can be placed at time (ms) or beat intervals, selected from a Grid submenu on the graph context menu, independently of the MS/BPM value unit.
- `OBS-SR2-ENV-007` `OBSERVED` (UG p.318, "Setting the Scaling"): The GLOBAL page exposes a single scaling control for all envelopes and a separate one for all LFOs. The guide names changing project BPM as the reason for the envelope scaler and simultaneous pattern changes as the reason for the LFO scaler; the LFO scaler can be expressed as a percentage or as a rate.

## 1.6 LFOs

- `OBS-SR2-LFO-001` `OBSERVED` (UG p.188, "Using LFOs"): There are ten LFOs, each with an independent control set. On an initialised patch only LFO 1 through LFO 6 are visible; LFO 7 through LFO 10 appear after LFO 6 is used (assigned). Visibility is therefore progressive-disclosure keyed to assignment, not a capacity change.
- `OBS-SR2-LFO-002` `OBSERVED` (UG p.189, "Drawing an LFO Graph"): Four drawing tools exist — Point, Flat, Ramp Up, Ramp Down. The three non-Point tools all operate at the current grid size.
- `OBS-SR2-LFO-003` `OBSERVED` (UG p.190, "Modifying LFOs"): The graph gesture grammar is: double-click adds or removes a point; Shift-click draws steps at the grid size (described as step-sequencer behavior); Option/Alt-drag a point snaps it to the grid; Option/Alt-drag any curve point moves all curve points at once; click-drag on the background rubber-band-selects points; Cmd/Ctrl-drag a point selects points for relative movement, where nearer points move more and farther points move less and the affected points display rainbow colouring; Ctrl-click (macOS) / right-click (Windows) opens the context menu; Shift-Cmd/Shift-Ctrl-click sets a point as the loopback position.
- `OBS-SR2-LFO-004` `OBSERVED` (UG p.191, LFO control table): LFO TYPE has five values: Normal, Path, Chaos: Lorenz, Chaos: Rossler, S&H.
- `OBS-SR2-LFO-005` `OBSERVED` (UG p.191, LFO control table): LFO MODE (retrigger) has three values with distinct semantics: FREE follows the host clock and ignores note timing; RETRIG restarts the LFO with each new note; ENVELOPE behaves like RETRIG but plays a single cycle and stops. In ENVELOPE mode a segment can be looped by setting a loopback point from a point's context menu, after which the LFO plays through and cycles back to that point.
- `OBS-SR2-LFO-006` `OBSERVED` (UG p.191, LFO control table): LFOs are polyphonic by default, giving each voice independent modulation; the MONO switch collapses this so one modulation applies to all voices.
- `OBS-SR2-LFO-007` `OBSERVED` (UG p.191, LFO control table): Loading an LFO preset via SHAPE overwrites the current graph. The same menu saves the current graph as a user preset.
- `OBS-SR2-LFO-008` `OBSERVED` (UG p.191, LFO control table): DIRECTION has three values: Forward, Reverse, Ping Pong.
- `OBS-SR2-LFO-009` `OBSERVED` (UG p.192, LFO control table): GRID sets the LFO graph grid; horizontal and vertical grid boxes are each double-clicked and typed independently. The grid governs point-snap and step-draw behavior.
- `OBS-SR2-LFO-010` `OBSERVED` (UG p.192, LFO control table): RATE is beat-synced by default. With BPM selected, right-clicking RATE offers Swing, which applies the SWING value set above the keyboard. With HZ selected, right-clicking RATE offers `10x`, multiplying the Hz range by ten for faster rates. The base Hz range is not stated in this section.
- `OBS-SR2-LFO-011` `OBSERVED` (UG p.192, LFO control table): TRIP and DOT set triplet and dotted timing on the rate control, and the guide gives their purpose as excluding triplet/dotted values when automating the LFO rate across evenly beat-divisible times.
- `OBS-SR2-LFO-012` `OBSERVED` (UG pp.192–193, LFO control table and callout): HOST has two distinct meanings depending on BPM. With BPM enabled, HOST anchors LFO phase to the host transport position, so changing rate (the example given is quarter note to one bar) may make the phase jump to stay aligned to the bar cycle. With BPM disabled — and the guide states this is a change from Serum 1 — HOST decides whether phase is computed from the host transport sample position on retrigger, making a FREE LFO deterministic across playbacks; disabling HOST gives a truly free-running LFO whose phase continues as if it had never stopped since the last playback start.
- `OBS-SR2-LFO-013` `OBSERVED` (UG pp.192–193, LFO control table): RISE is the time over which the LFO graph shape takes over from a fixed output held at the leftmost graph point's value; DELAY is the time before the rise begins; SMOOTH smooths the output to avoid abrupt jumps without drawing ramps per segment; PHASE sets the start position and can be snapped to the vertical grid lines via its context menu.
- `OBS-SR2-LFO-014` `OBSERVED` (UG p.193, "Using the LFO Editor"): A dedicated LFO Editor offers the same tool set on a larger canvas for finer adjustment.
- `OBS-SR2-LFO-015` `OBSERVED` (UG pp.197–198): Shapes cross between the oscillator and LFO domains in both directions. `Wavetable A to LFO` (and the B/C equivalents) in the LFO Default menu copies the oscillator's currently selected frame into the LFO; Option/Alt-dragging an LFO tab onto an OSC A/B/C wavetable display copies the LFO shape into that oscillator.
- `OBS-SR2-LFO-016` `OBSERVED` (UG pp.198–200, "Modulating LFO Points"): Individual LFO points and curves are themselves modulation destinations, routed through named LFO busses so that one source can drive multiple points without duplicate assignments. Assignment is by right-click → Modulate X / Modulate Y → choose an LFO bus → choose a source, or by dragging a source onto a point and dropping on the X or Y target that appears. Initially only LFO Bus 1 exists. The graph then shows a shaded bar spanning the modulation range. Multiple points may be selected and configured in a single assignment.

## 1.7 Modulation assignment, depth, and the matrix

- `OBS-SR2-MOD-001` `OBSERVED` (UG pp.187, 194, 207): Modulation is assigned by dragging a source tab (ENV n, LFO n, VELO, NOTE, a macro selector, or an oscillator/filter module label) onto a control. A `+` sign on the pointer signals a valid destination. The number of destinations a source drives is shown as a numeral on the source tab, and hovering the tab lists the destinations in a tooltip.
- `OBS-SR2-MOD-002` `OBSERVED` (UG p.208, "Using Oscillators and Filters as Modulation Sources"): The output of any oscillator or any filter may be used as a modulation source by dragging its module label to a control.
- `OBS-SR2-MOD-003` `OBSERVED` (UG p.195, "Setting the Modulator Depth"): Depth is shown as a blue halo around the destination knob. A smaller halo at the knob's top-left reveals an up/down arrow control on hover; dragging it changes depth and resizes the halo. Option/Alt-dragging the main knob itself is the documented shortcut for the same operation.
- `OBS-SR2-MOD-004` `OBSERVED` (UG p.195): When a modulator is assigned but its source is not currently selected, the halo is gray; adjusting depth then requires first selecting that source's tab.
- `OBS-SR2-MOD-005` `OBSERVED` (UG p.196, "Setting Negative Modulation Depths"): Depth may be negative; the halo turns a lighter blue to indicate the source's influence is inverted.
- `OBS-SR2-MOD-006` `OBSERVED` (UG p.196): The polarity chosen by a drag-and-drop assignment is inferred from the destination control's geometry — a centred control such as DETUNE gets bidirectional, a non-centred control such as filter RES gets unidirectional. Shift-Option/Shift-Alt-clicking a knob with a visible modulation assignment toggles the type without opening the matrix.
- `OBS-SR2-MOD-007` `OBSERVED` (UG p.314, Preferences table): The preference `Limit Mod depth on drop (based on knob value)` reduces the assigned depth at drop time so the modulated maximum does not exceed the parameter's maximum. The worked example is a modulator dropped on an oscillator LEVEL knob at 75%, which is assigned 25% depth so a full-scale modulator reaches exactly 100%.
- `OBS-SR2-MOD-008` `OBSERVED` (UG pp.200–201, "Using Context Menus with Controls"): Nearly every control's context menu carries the same command set: Mod Source submenu, Aux Source submenu, Edit Custom Curve, Bypass Modulator, Remove Modulator, Remove All Modulators, Reset Control, MIDI Learn, Remove MIDI cc, Lock Parameter. Bypassing turns the halo gray and places a check mark on the menu item; the same bypass is available from the source tile's own context menu.
- `OBS-SR2-MOD-009` `OBSERVED` (UG p.209, "Using the Modulation Matrix"): The matrix holds exactly 64 slots per patch, one destination parameter per slot, drawing from 49 modulation sources. Drag-and-drop assignment and matrix editing are two views of the same state — a drag creates a matrix row and vice versa.
- `OBS-SR2-MOD-010` `OBSERVED` (UG pp.210–211, SOURCE table): Some sources exist only in the matrix and cannot be created by dragging. The enumerated matrix-only set is: Active Voices (active voice count divided by the POLY maximum), Note-On Alt. 1/2 (alternating 0 and 1 at each note-on, with Alt 2 the inverse of Alt 1), Note-On Rand (Discrete) (each destination receives a *different* value at note-on, unlike Note-On Rand 1/2 which send the same value to every destination they drive), Note-On Rand 1 and 2 (two independent per-note-on random numbers), oscillator outputs including NOISE and SUB, Release Velocity, Voice Index (set at note-on from the Voice panel's current index divided by the number of active steps), Voice Mod 1/2 (set at note-on from the current Voice panel step), Expression/MPE X/Y/Z, filter outputs, Mod Wheel, Aftertouch (channel pressure), Poly Aftertouch, Pitch Bend, and Fixed.
- `OBS-SR2-MOD-011` `OBSERVED` (UG p.211, matrix table): Each row exposes a source curve (CRV) that reshapes the source non-linearly, with 50% documented as linear and a gray curve meaning bypassed. Double-clicking the curve, or choosing Editable Curve, opens an editor with RISE and FALL smoothing controls that act as a slew limiter on the source.
- `OBS-SR2-MOD-012` `OBSERVED` (UG p.211, matrix table): AMOUNT is a bidirectional slider whose left half inverts the source before it reaches the destination; Cmd/Ctrl-click resets it to zero. POL selects unidirectional or bidirectional, and the guide frames the choice as whether the destination knob position should represent the beginning or the middle of the modulation range.
- `OBS-SR2-MOD-013` `OBSERVED` (UG p.211, matrix table): Each row also carries an AUX SOURCE whose default behavior multiplies it against the primary source — the worked example is LFO 1 with Mod Wheel as aux, where LFO 1 is inaudible until the wheel rises above zero. INV value-inverts the aux source, so in the same example full modulation occurs at minimum wheel and none at maximum. The aux source has its own CRV curve with the same 50%-linear convention, and an OUTPUT control scales the final result.
- `OBS-SR2-MOD-014` `OBSERVED` (UG pp.212–213): Rows are reordered by dragging a row handle, bypassed individually with a per-row bypass button, and removed individually with a per-row remove button. The matrix view expands and reverts via a button or Option-F / Alt-F.
- `OBS-SR2-MOD-015` `OBSERVED` (UG p.214, "Performing Matrix Operations"): The matrix menu offers six operations: Sort by Source (ascending), Sort by Destination (ascending), `Lock Matrix (Keep Assignments on Preset Change)`, `Create Vibrato (Unused LFO->Pitch via Wheel)` which builds a next-available-LFO → Main Tuning modulation driven by the Mod Wheel, `Create Velo->Amp Assignment`, and `Apply and Delete Macros`.
- `OBS-SR2-MOD-016` `OBSERVED` (UG p.214, "Performing Matrix Operations"): `Apply and Delete Macros` is a documented destructive bake: for every parameter assigned to a macro it folds the macro's current offset into the parameter's stored value, then removes all macro modulation rows from the matrix.
- `OBS-SR2-MOD-017` `OBSERVED` (UG p.206, "Using Macros"): There are exactly eight macros. A macro is both a modulation source and a valid modulation destination, and the guide gives the documented reason: making a macro an aux source and then modulating that macro from another matrix row yields effectively two stacked scaling sources on one destination.
- `OBS-SR2-MOD-018` `OBSERVED` (UG p.207, "Assigning a Macro" callout): Dragging one macro onto another **swaps** their assignments.
- `OBS-SR2-MOD-019` `OBSERVED` (UG pp.201–205, "Setting Velocity and Notes"): MIDI velocity and MIDI note number are each exposed as a user-drawn response graph (VELO and NOTE tabs) that is then dragged onto destinations like any other modulation source. Graph editing is: double-click adds/removes a point, drag moves a point, drag a curve point shapes a segment, Option/Alt-drag a curve point shapes all segments simultaneously. Each tab's context menu offers `Legato (Portamento Time)`, applying portamento to that curve when a note is triggered while another is held, and `Init Graph`, which clears added points back to a straight diagonal.
- `OBS-SR2-MOD-020` `OBSERVED` (UG p.324, Appendix A): Initialisation is granular at the modulation layer: `Init Preset`, `Init LFOs + LFO Mods`, and `Init Modulations` are three separate commands, the last leaving the LFOs themselves untouched.

## 1.8 Clip module (in-instrument sequencer)

- `OBS-SR2-CLIP-001` `OBSERVED` (UG p.220, "Exploring the CLIP Module"): The CLIP module holds 12 clip slots per bank, organised into GLOBAL, CLIP SETTINGS, piano roll, macros, and MIDI-out panes. A clip is defined as notes plus controller data carrying pitch, length, position, and velocity.
- `OBS-SR2-CLIP-002` `OBSERVED` (UG p.221, "Setting Global Parameters"): TRIGGER MODE is per-bank and has two values: MONO allows one clip playing at a time, POLY allows several simultaneously.
- `OBS-SR2-CLIP-003` `OBSERVED` (UG p.221): EDIT ALL is a per-bank switch that broadcasts clip-parameter edits to all 12 clips; disabled, edits apply only to the selected clip. Holding Option/Alt while editing a clip parameter performs the same broadcast for that single edit.
- `OBS-SR2-CLIP-004` `OBSERVED` (UG p.222, "Creating a New Clip Bank"): Initialising the clip bank affects clip-bank settings only and explicitly leaves oscillators, filters, arpeggiators, and other sound-design state untouched. Module scope is therefore an isolation boundary for initialisation.
- `OBS-SR2-CLIP-005` `OBSERVED` (UG p.223, "Saving Clip Banks"): A modified bank preset is marked with a trailing asterisk. Saving a bank that already exists on disk opens a dialog defaulting to a new name, so incremental saves are the default path and overwrite requires deliberately re-selecting the existing filename.
- `OBS-SR2-CLIP-006` `OBSERVED` (UG p.225, "Working with the Piano Roll"): Notes are added by double-clicking, and the most recently added note is drawn in orange. Selection is by drag, extended by Shift-drag or successive Shift-clicks.
- `OBS-SR2-CLIP-007` `OBSERVED` (UG p.225): Dragging across empty piano-roll space selects a **time range** rather than notes; notes straddling the range boundary are split. Pasting a time range overwrites all existing notes in the destination range, which the guide calls out as differing from pasting notes.
- `OBS-SR2-CLIP-008` `OBSERVED` (UG p.226, arrow-key table): Arrow keys transform selections: Up/Down move by one semitone, Shift+Up/Down by one octave, Left/Right by one grid position, Shift+Left/Right shorten and lengthen. As printed, the guide's table maps Left to "one position to the right" and Right to "one position to the left"; Appendix G (p.352) prints the same inversion, so the two official statements agree with each other but are internally counter-intuitive (recorded as `GAP-SERUM2-0009`).
- `OBS-SR2-CLIP-009` `OBSERVED` (UG pp.226–227, note-operation table): Fifteen note operations are documented with bindings: Cut (Cmd/Ctrl-X), Copy (Cmd/Ctrl-C), Paste (Cmd/Ctrl-V), Duplicate (Cmd/Ctrl-D), Delete (Backspace), Chop (Cmd/Ctrl-U), Conform to Scale (Cmd/Ctrl-K), Legato (Cmd/Ctrl-L), Mute (`0`), Quantize (Cmd/Ctrl-Q), Reverse (Cmd/Ctrl-R), Scale Time 50% (`/`), Scale Time 200% (`*`), Double Entire clip (Cmd/Ctrl-E), Select All (Cmd/Ctrl-A). Two further operations — Scale Entire clip 50% and Scale Entire clip 200% — exist with no keyboard binding.
- `OBS-SR2-CLIP-010` `OBSERVED` (UG p.226): Duplicate places copies at the timeline, and the timeline is defined as the end of the current selection — so where the selection ends determines where the duplicate begins.
- `OBS-SR2-CLIP-011` `OBSERVED` (UG pp.226–227): Scale Time 50%/200% halve or double note times and durations **without** changing clip length, whereas Scale Entire clip 50%/200% change clip length and note durations together (the printed examples: a two-bar clip of eighth notes becomes a one-bar clip of sixteenths; a one-bar clip of sixteenths becomes a two-bar clip of eighths). Double Entire clip appends a duplicate and doubles the clip length.
- `OBS-SR2-CLIP-012` `OBSERVED` (UG p.227): Deleting a single note is a double-click on it; deleting a selection uses Delete (macOS) or Backspace (Windows). Note that the operations table on p.226 lists Backspace for both platforms, so the two statements are not phrased identically.
- `OBS-SR2-CLIP-013` `OBSERVED` (UG p.227): Selecting a note is silent by default; a headphone toggle makes selection audition the note.
- `OBS-SR2-CLIP-014` `OBSERVED` (UG p.227): Piano-roll key commands only act when the note grid or the automation lane holds keyboard focus, which is given by clicking the corresponding background, and a keyboard icon near the top right indicates which pane has focus. Separately, the GLOBAL `Keyboard shortcuts` preference must be ON for any of them to work. Two independent gates therefore govern key-command dispatch.
- `OBS-SR2-CLIP-015` `OBSERVED` (UG p.228, "Setting the Grid Size"): The piano-roll grid defaults to 1/16 notes and is changed by dragging the grid-size button or by right-clicking it for a menu.
- `OBS-SR2-CLIP-016` `OBSERVED` (UG p.229, "Zooming the Piano Roll"): Navigation gestures are: Cmd-Option / Ctrl-Alt drag on background scrolls in any direction; Shift-Option / Shift-Alt drag zooms in any direction; Shift-Cmd / Shift-Ctrl drag on the note grid draws a marquee and zooms to it on release; mouse wheel scrolls vertically and Shift+wheel horizontally; Option/Alt+wheel zooms vertically and Cmd/Ctrl+wheel zooms horizontally; the wheel over the timeline zooms horizontally.
- `OBS-SR2-CLIP-017` `OBSERVED` (UG pp.230–231, "Folding the Piano Roll"): The piano roll shows the full chromatic range by default. Fold hides unused notes. With a key and scale selected, fold collapses to the scale's notes; holding Cmd/Ctrl while clicking fold shows scale notes *plus* used notes, distinguishing in-scale (blue background) from out-of-scale (gray background).
- `OBS-SR2-CLIP-018` `OBSERVED` (UG p.232, "Managing the Clip Length"): Clip length and clip start are set by dragging right and left flags. A separate start-offset marker, dragged from the left, determines where playback begins when the clip is triggered — so trigger start position is decoupled from clip start.
- `OBS-SR2-CLIP-019` `OBSERVED` (UG p.233, marker context menu): The start-offset marker's menu has two entries. `Wrap Clip to Begin Here` resets the offset marker to the start marker, moving all notes and automation with it and wrapping anything that preceded the offset marker around to the end of the clip. `Quantize` both quantises the offset marker's position under modulation and defines the time division by which successive keys offset playback start when KB SPAN is set to Offset.
- `OBS-SR2-CLIP-020` `OBSERVED` (UG p.234, clip settings table): LENGTH is expressed in bars, beats, and 16th notes.
- `OBS-SR2-CLIP-021` `OBSERVED` (UG p.234, clip settings table): KB SPAN governs MIDI-note triggering with four values: Mono and Poly play the clip transposed by the played note **relative to C3**; Offset starts the clip from a different position per note as set by the offset quantize division; Off disables it.
- `OBS-SR2-CLIP-022` `OBSERVED` (UG p.234, clip settings table): MODE sets playhead movement with five documented non-linear options — Random (jump between slices at random), Rand.No Dup (as Random, never the same slice twice consecutively), Rand.Start (jump back to a slice each time the playhead reaches the clip end), Rand.End (play a random number of slices then jump back to the start), and Static (only events at the start position are sent and the playhead does not move, which the guide names as the way to make each clip fire a different chord or a different set of macro values). The random modes take an associated time value that divides the clip into slices of that length.
- `OBS-SR2-CLIP-023` `OBSERVED` (UG p.234, clip settings table): Four further per-clip fields govern launch and gating: RATE (playback speed), LAUNCH QUANT (the interval at which a triggered clip syncs to the clock/DAW), RETRIG (whether a trigger restarts the clip or immediately syncs the playhead to the clock/DAW), VELO TRIG (whether the clip's note velocities are scaled by the incoming note's velocity), and NOTE GATE (whether a note-off stops a clip triggered by MIDI input). TRANS sets per-clip transposition.
- `OBS-SR2-CLIP-024` `OBSERVED` (UG p.235, clip operations table): Per-clip operations are Rename Clip (clips default to names 1–12 left to right), Copy Clip (notes plus settings including the name, to an internal clipboard), Paste Clip, Erase Clip, and Set as Preview Clip. Copying a clip between two Serum instances is explicitly not possible.
- `OBS-SR2-CLIP-025` `OBSERVED` (UG p.235): `Set as Preview Clip` designates the MIDI sequence played when the preset is previewed in the browser; absent one, a fallback clip is used.
- `OBS-SR2-CLIP-026` `OBSERVED` (UG p.236, "Triggering Clips"): A clip is launched by its slot play button, which becomes a stop button. Clip slots are laid out like a keyboard and can be played from the CLIP keyboard while other pages are in view; a pressed key highlights green, pressing the same key stops the clip, pressing another launches that clip. A small green indicator flashes in rhythm with the played notes, and is absent when the launched clip contains no notes.
- `OBS-SR2-CLIP-027` `OBSERVED` (UG p.236): Every aspect of a clip — notes, clip settings, and the underlying patch — may be edited while the clip is playing.
- `OBS-SR2-CLIP-028` `OBSERVED` (UG pp.237–238, "Recording Your Clips"): Recording has two modes. OVERDUB loops continuously between the start and end markers, accumulating notes each pass. EXTEND grows the timeline until recording stops or the mode is switched. Modes may be switched at any time, including mid-record. A metronome toggle sits alongside.
- `OBS-SR2-CLIP-029` `OBSERVED` (UG p.238): Recorded material has an explicit two-state commit model. Newly played notes appear red (uncommitted); a commit action turns them green; an undo action discards the uncommitted pass only. Finishing recording commits everything to green, and the clip keeps playing until its slot's stop button is pressed.
- `OBS-SR2-CLIP-030` `OBSERVED` (UG p.239, "Managing MIDI Out"): CLIP MIDI OUT has three values: Off (default; nothing is sent to the host), Clip Player (CLIP module output only, with **no** key/scale pitch quantising applied), and On (CLIP output routed through the ARP module if enabled, with key/scale quantising applied). Regardless of the setting, the on-screen display shows the notes reaching the internal synth engine.
- `OBS-SR2-CLIP-031` `OBSERVED` (UG p.265, "Managing MIDI Out"): The arpeggiator chapter states the same three-value control with a different description of `On` — MIDI from both the CLIP player and the arpeggiator. The two chapters agree that Off is the default and that Clip Player restricts output to the clip module.
- `OBS-SR2-CLIP-032` `OBSERVED` (UG pp.239–240, "Routing MIDI to Another Instrument"): With MIDI OUT set to On or Clip Player, Serum's generated MIDI can drive another instrument track in the host. The guide documents exactly one host procedure, for Apple Logic Pro X, using the destination track's Internal MIDI In → Instrument Output selector.
- `OBS-SR2-CLIP-033` `OBSERVED` (UG p.241, "Configuring the Clip Module"): The CLIP module context menu has two entries: `Lock Module`, which preserves the whole module including all loaded clips across sound-preset changes, and `MIDI Input Trigger Octave`, which selects the octave whose notes trigger clips or turns triggering off. The default is the lowest octave of the MIDI note range.
- `OBS-SR2-CLIP-034` `OBSERVED` (UG pp.241–243, "Using Macros"): Macros are assignable to controls inside the CLIP module by dragging the macro selector; the guide states not all controls are valid destinations. Macro automation can be recorded into a clip by dragging the macro knobs during recording, and a macro's destination list is shown on hover (the worked example destination is `Clip 1 Rate`).

## 1.9 Arpeggiator

- `OBS-SR2-ARP-001` `OBSERVED` (UG p.245, "Exploring the Arpeggiator"): The ARP module holds 12 arpeggiators per bank and is organised into GLOBAL, PATTERN, TRANSPOSE, PLAYBACK, RETRIGGER, and VELOCITY panes.
- `OBS-SR2-ARP-002` `OBSERVED` (UG p.246, "Setting Global Parameters"): LAUNCH QUANT is a bank-level setting specifying the interval at which a triggered arp syncs to the clock/DAW. EDIT ALL broadcasts parameter edits across all 12 arp slots, with Option/Alt-while-editing as the per-edit equivalent — structurally identical to the CLIP module's arrangement.
- `OBS-SR2-ARP-003` `OBSERVED` (UG p.247, "Creating a New Arp Bank"): Initialising the arp bank affects arp-bank settings only and leaves oscillators, filters, clips, and other sound-design state untouched.
- `OBS-SR2-ARP-004` `OBSERVED` (UG pp.247–248, "Saving Arp Banks"): Modified arp banks show a trailing asterisk and the save dialog defaults to a new name, matching the clip-bank save policy.
- `OBS-SR2-ARP-005` `OBSERVED` (UG p.248, "Setting the Arp Pattern"): SHAPE selects the arp pattern from standard up/down forms plus named shapes including Converge and Diverge and a set of random shapes. Rate is set in BPM or Hz with a knob and an equivalent numeric field, and TRIP and DOT toggle triplet and dotted timing.
- `OBS-SR2-ARP-006` `OBSERVED` (UG pp.249–250, "Creating a Custom Pattern"): Choosing `Pattern` in SHAPE reveals a dedicated pattern editor in the top half of the interface, with a settings panel on the left and a graph on the right. Initialising the pattern affects only the current pattern and not the rest of the arp bank.
- `OBS-SR2-ARP-007` `OBSERVED` (UG p.251, pattern settings table): Pattern LENGTH is expressed in bars, beats, and 16th notes — the same unit triple as clip LENGTH.
- `OBS-SR2-ARP-008` `OBSERVED` (UG p.251, pattern settings table): Pattern MODE has eight playhead behaviors: Normal, Reverse, Pendulum, Random, Rand Start, Rand End, One Shot, Static. TIME governs how often random modes jump, with a documented range from a 1/16th note to four bars.
- `OBS-SR2-ARP-009` `OBSERVED` (UG p.251, pattern settings table): STEP MODE has four values — Normal, New Only, Chord, Chord (new). Chord triggers all held notes on each step with voicing determined by step numbers. The `new` variants trigger a step only when the input note arrives at exactly the same time as the step fires.
- `OBS-SR2-ARP-010` `OBSERVED` (UG p.251, pattern settings table): WRAP defines the treatment of pattern steps that are fewer or more numerous than the held keys; RANGE defines how such steps are transposed; PITCH is the wrap transpose, documented as 0 to 24 semitones.
- `OBS-SR2-ARP-011` `OBSERVED` (UG p.253, "Using the Arp Graph Editor"): The arp graph editor reuses the CLIP piano roll's interaction model — double-click to add an event (newest drawn orange), drag to select, cut/copy/paste, move — and adds two dedicated lanes: double-clicking the Accent lane accents the corresponding event, double-clicking the Strum lane adds strumming. Automation lanes control further parameters over time.
- `OBS-SR2-ARP-012` `OBSERVED` (UG pp.254–261, transpose range shape table): Transpose is a two-knob system — SHIFT (the semitone amount, positive or negative, applied per repetition) and RANGE (how many times the pattern is transposed) — plus a range **shape** chosen by right-clicking RANGE. Sixteen shapes are documented: Up, Down, Up/Down, Down/Up, Up+Down, Down+Up, Thumb Up, Thumb UD, Pinky Up, Pinky UD, Converge, Diverge, Con+Diverge, Chord, Random, Rnd.NoDup, Rnd.Drift, Rnd.Once. Chord uses SHIFT and RANGE to sound a chord instead of an arpeggio; Rnd.Drift biases the randomisation toward drifting; Rnd.Once randomises once and then repeats that result.
- `OBS-SR2-ARP-013` `OBSERVED` (UG p.261, "Playback Settings"): LATCH holds notes without the keys being held. THRU passes incoming notes to the output the way a hardware MIDI THRU port would; with THRU disabled the arpeggiator consumes its input.
- `OBS-SR2-ARP-014` `OBSERVED` (UG p.262, playback knob table): Four playback knobs are documented: OFFSET (offsets the order of arpeggiated notes), REPEATS (how many times the pattern and transpose range repeat), GATE (note length relative to RATE), and CHANCE (per-note play probability). Right-clicking CHANCE offers `Pre`, applying the probability test *before* the SHAPE pattern advances, which the guide states guarantees that the next note played is always the next one in the sequence.
- `OBS-SR2-ARP-015` `OBSERVED` (UG p.262, callout): While the arpeggiator is enabled, incoming MIDI CC64 (sustain) controls the latch rather than ordinary note sustain. This is a documented re-binding of a standard MIDI controller conditional on module state.
- `OBS-SR2-ARP-016` `OBSERVED` (UG p.262, "Retrigger Settings"): Retrigger has four independent enables: LAUNCH (retrigger when the slot is launched), RATE (retrigger at a set interval), NOTE (retrigger on any incoming note), and FIRST (retrigger only on the first incoming note, the documented case being held chord notes).
- `OBS-SR2-ARP-017` `OBSERVED` (UG p.262, "Velocity Settings"): Arp velocity decay is a separate enabled block with three controls: RETRIG (reset the decay back to incoming velocities whenever retrigger fires), DECAY (rate of change), and TARGET (the velocity the decay moves toward). The target may be above or below the incoming velocity, so it raises as well as lowers.
- `OBS-SR2-ARP-018` `OBSERVED` (UG p.263, arp operations table): Per-arp operations are Rename Pattern, Copy Pattern, Paste Pattern, Erase Pattern, and Show Pattern Names. Arps are named by default after their pattern shape and rate, in the printed form `Up (1/16)` or `Down (1/32)`. Copying a pattern between two Serum instances is explicitly not possible.
- `OBS-SR2-ARP-019` `OBSERVED` (UG p.264, "Triggering the Arpeggiator"): An arp is launched from its slot play button or from the ARP keyboard, whose keys highlight purple. Pressing the same key **relaunches** the arp — unlike the CLIP keyboard, where the same key stops the clip. Stopping an arp is instead done by removing its MIDI input: releasing keys, stopping a playing clip, or disabling latch.
- `OBS-SR2-ARP-020` `OBSERVED` (UG p.266, "Configuring the Arp Module"): The ARP module context menu mirrors the CLIP module's: `Lock Module` (preserves the module and all arps across sound-preset changes) and `MIDI Input Trigger Octave` (default: the lowest octave of the MIDI note range, or Off).

## 1.10 On-screen keyboard, key/scale, swing, and oscillator mapping

- `OBS-SR2-KEYS-001` `OBSERVED` (UG p.267, "Transpose"): Keyboard TRANSPOSE spans −24 to +24 semitones (two octaves each way). It is set by dragging the field, stepped one semitone at a time by up/down arrows, and moved in 12-semitone increments by the mouse wheel over the field.
- `OBS-SR2-KEYS-002` `OBSERVED` (UG pp.25, 268): TRANSPOSE, KEY, and SCALE apply to both incoming MIDI and the output of the CLIP and ARP modules. Notes outside the selected scale conform to it automatically.
- `OBS-SR2-KEYS-003` `OBSERVED` (UG p.268, "Setting the Key and Scale"): After a key and scale are chosen, the CLIP piano roll highlights the key's root note, draws in-scale notes on a gray background, and draws out-of-scale notes on a darker gray background. The guide describes the available scale set only as comprehensive and does not enumerate it.
- `OBS-SR2-KEYS-004` `OBSERVED` (UG p.269, "Setting Swing"): SWING defaults to OFF, and moving off that value reveals a second field for the swing division. The guide states the numeric range of swing depends on the host DAW because Serum matches the host's display convention, giving Ableton Live's 12.5%–87.5% and FL Studio's −150%–150% as the two worked examples, and states that identical values in Serum and the host should produce identical swing.
- `OBS-SR2-KEYS-005` `OBSERVED` (UG pp.269–271, "Oscillator Mapping"): The oscillator mapping editor assigns note ranges independently to each oscillator **and to the arpeggiator**. Ranges are set by dragging a range's left or right edge, moved by dragging the range body, and double-clicked to type exact values using the notation shown on the keyboard beneath the ranges.
- `OBS-SR2-KEYS-006` `OBSERVED` (UG p.271): A FOLD checkbox per range decides what happens to notes outside it: unselected, out-of-range notes are ignored; selected, they are folded into the range. The documented use is constraining a sub-bass oscillator to one low octave regardless of the played octave.
- `OBS-SR2-KEYS-007` `OBSERVED` (UG p.271): A WARP checkbox per range lets an oscillator continue acting as a warp source for other oscillators even when the played note falls outside its own note range. The worked example is OSC A warping from B: enabling WARP on OSC B preserves the warp on OSC A for notes outside OSC B's range.
- `OBS-SR2-KEYS-008` `OBSERVED` (UG pp.272–273, "Mapping Velocity Ranges"): The same editor has a VEL mode mapping velocity ranges for oscillators and the arpeggiator, over a documented complete range of 1 to 127. It is also reachable by right-clicking any oscillator header and choosing `Edit Note Ranges`.

## 1.11 FX rack

- `OBS-SR2-FX-001` `OBSERVED` (UG p.152, "Using Serum FX"): There are 13 FX processors plus 3 splitter module types, usable in any order and combination, and multiple instances of the same processor are permitted.
- `OBS-SR2-FX-002` `OBSERVED` (UG p.153, "Selecting a Rack"): There are exactly three FX racks — MAIN, BUS 1, BUS 2 — each processing its own channel.
- `OBS-SR2-FX-003` `OBSERVED` (UG p.155, "Adding Modules"): Signal flow through a rack is top to bottom, and everything routed to MAIN passes through the rack's modules before the master volume and output.
- `OBS-SR2-FX-004` `OBSERVED` (UG pp.152–153): The FX rack and list view expand and revert with a button or Option-F / Alt-F — the same binding the modulation matrix uses for the same purpose (UG p.212).
- `OBS-SR2-FX-005` `OBSERVED` (UG p.156, "Reordering Modules" / "Copying a Module"): Modules are reordered by dragging in either the list view or the rack view, with a yellow insertion line. Option/Alt-drag duplicates a module without its modulations; Shift-Option/Shift-Alt-drag duplicates it with them — the same modifier grammar the oscillator/filter modules use.
- `OBS-SR2-FX-006` `OBSERVED` (UG p.157, "Bypassing a Module"): Bypass is per module, shown red when active, and framed by the guide as a temporary A/B device rather than a way to disable an effect (removal is the recommended way to deactivate). Option/Alt-clicking any bypass button toggles bypass for every FX on that bus, and the same gesture works from the MIXER page's FX bypass buttons.
- `OBS-SR2-FX-007` `OBSERVED` (UG p.158, rack operations table): Right-clicking the rack background exposes whole-rack operations: add a module, Cut FX Bus, Copy FX Bus, Paste FX Bus, Clear FX Bus, Lock FX Bus, Lock All FX Busses, Load FX Bus, Save FX Bus. Cut/Copy/Paste operate on a rack-level clipboard for moving or duplicating an entire chain between MAIN, BUS 1, and BUS 2.
- `OBS-SR2-FX-008` `OBSERVED` (UG p.158, rack operations table): `Lock FX Bus` keeps that rack's modules in place across preset changes, but the guide states that modulation assignments to parameters inside a locked rack **are cleared** on preset change. Locking preserves structure, not modulation.
- `OBS-SR2-FX-009` `OBSERVED` (UG pp.163–164, Compressor): Turning the compressor RATIO fully up engages a different DSP path described as a true peak limiter rather than a high-ratio compressor. Engaging it changes the attack-time range to 0–10 ms. The guide notes the limiter can introduce latency and exposes `Limiter Latency Comp` on the RATIO knob's context menu to compensate for it.
- `OBS-SR2-FX-010` `OBSERVED` (UG pp.164–165, Convolve): The Convolve module applies a chosen impulse response, selectable from a menu or loaded from outside the Serum 2 Presets folder by dragging files onto the IR display or choosing `Load IR`. An embed icon allows the impulse response to be embedded into the preset. Controls include SIZE (stretch/contract the impulse), TONE (filter the impulse), a minimum-phase conversion, and PRE-DLY (offset the impulse in time).
- `OBS-SR2-FX-011` `OBSERVED` (UG p.162, Chorus): The chorus RATE unit follows its BPM switch — musical divisions from 8 bars to a 1/32nd note when BPM is on, and 0 Hz to 20 Hz when BPM is off.

## 1.12 Global settings, quality, tuning, and MPE

- `OBS-SR2-GLOB-001` `OBSERVED` (UG p.312, "Exploring Global Settings"): Global settings split into two persistence classes — those saved with the preset/song/patch and those saved as part of the application and shared by all presets. The GLOBAL page has four panes: Preferences, Voice Control, Quality, Tuning, and it also displays the current version and build date.
- `OBS-SR2-GLOB-002` `OBSERVED` (UG pp.313–314, Preferences table): User-interface preferences are Help Tooltips, Param value tooltips, Double-click params (choosing whether double-click resets to the init value or opens a numeric entry box), Mouse wheel param control (a **disable** switch for hover-wheel knob adjustment), Keyboard shortcuts (whether Serum responds to the computer keyboard at all, with the stated purpose of stopping Serum taking keyboard focus from the host), and Default waveform view (2D, stated as the default, or 3D).
- `OBS-SR2-GLOB-003` `OBSERVED` (UG p.314, Preferences table): Three MPE preferences exist: `MPE enabled by default` (whether new instances start with MPE on), `MPE Pitch Bend (also) maps to Expr X`, and `MPE Expr Y acts bi-directional` (whether note expression Y is unipolar or bipolar, so it can be matched to the host or controller convention).
- `OBS-SR2-GLOB-004` `OBSERVED` (UG p.314, Preferences table): By default Serum maps MIDI pitch bend to per-note pitch bend and CC10 (pan) to note expression X. The `MPE Pitch Bend (also) maps to Expr X` preference exists for controllers that transmit pitch bend for X-axis movement, mapping those gestures to note expression X in addition to per-note pitch bend.
- `OBS-SR2-GLOB-005` `OBSERVED` (UG p.315, Preferences table): `Mod Wheel -> WT Pos (when WT Editor is open)` makes the mod wheel scan wavetable indices 1–256 while the Wavetable Editor is active — a documented context-dependent re-binding of a standard MIDI control.
- `OBS-SR2-GLOB-006` `OBSERVED` (UG p.315, Preferences table): `Silence note + FX tails when host transport stops` mutes effects and sustaining notes when the host DAW stops.
- `OBS-SR2-GLOB-007` `OBSERVED` (UG pp.315, 26, 324): MIDI CC map loading has a documented precedence chain. Normally Serum loads `Serum 2 Presets/System/MIDI CC Maps/Default.SerumMIDIMap` on new-instance creation, on Init Preset, and on preset load. Enabling `Load MIDI Map from Presets` makes preset load use the map saved with the preset instead. MIDI CC assignments are always saved with the DAW session and always saved into a preset, but are only *loaded* from the preset when that preference is enabled — and p.26 states the preference is disabled by default.
- `OBS-SR2-GLOB-008` `OBSERVED` (UG p.315, Preferences table): `Use Ultra quality when rendering` makes offline renders/bounces use ultra quality regardless of the live quality setting, with the guide's rationale being that offline rendering removes the performance cost.
- `OBS-SR2-GLOB-009` `OBSERVED` (UG p.319, "Setting the Quality"): Quality is an oversampling selector with exactly three named steps: Draft = 1× (no oversampling), High = 2×, Ultra = 4×. A lock button makes Serum ignore the quality configuration stored in any preset it subsequently loads and keep the locked settings instead.
- `OBS-SR2-GLOB-010` `OBSERVED` (UG p.319, quality settings table): `S1 Compatibility Mode` is enabled **automatically** when a Serum 1 preset is loaded, in order to preserve sonic similarity against what the guide calls a completely rebuilt sound engine. Disabling it lets Serum 1 presets use the Serum 2 DSP updates. Compatibility is therefore per-preset state with an automatic trigger, not a global mode.
- `OBS-SR2-GLOB-011` `OBSERVED` (UG p.320, quality settings table): `Disable Smoothing` turns off automation parameter smoothing. The guide states Serum supports sample-accurate automation and names fast rhythmic automation as the case where smoothing should be defeated. It further states smoothing also applies to parameter changes made by mouse on on-screen controls, so the setting is not automation-only.
- `OBS-SR2-GLOB-012` `OBSERVED` (UG pp.316–319, "Setting the Voice Control"): Voice Control defines per-voice behavior across a selectable subset of oscillators (all selected by default) using a step sequence whose length is set by clicking a number from 1 to 8. It supports factory and user presets, an Init command, and a save-with-name dialog.
- `OBS-SR2-GLOB-013` `OBSERVED` (UG p.318, randomisation table): Voice Control randomisation covers exactly four dimensions, each per voice: PAN (stereo position, as a percentage), DETUNE (tuning offset, in cents), CUTOFF (filter cutoff, as a percentage), ENVS (envelope offset, as a percentage).
- `OBS-SR2-GLOB-014` `OBSERVED` (UG p.320, "Setting Concert Pitch"): Concert pitch is a settable field; the guide describes the widely accepted concert pitch as A4 at 440 Hz, defining A4 as the A above middle C and the fourth A key on a piano.
- `OBS-SR2-GLOB-015` `OBSERVED` (UG p.320, "Using a Tuning File"): Tuning may come from a per-instance `.tun` file loaded via `Load Tuning` (and cleared via `Clear Tuning`), or from a project-wide MTS-ESP source.
- `OBS-SR2-GLOB-016` `OBSERVED` (UG p.321, "Using MTS-ESP to Set the Tuning"): MTS-ESP support is enabled by default and can be unchecked. `MTS-ESP Note-On Only` fixes a note's tuning at note-on so it will not change mid-note when the global tuning updates. Precedence is explicit: a loaded `.tun` file always takes precedence over MTS-ESP, which is what allows a single instance to be tuned differently from the project. When the oscillator pitch mode is Steps, OCT/SEM move in periods and steps as defined by the active MTS-ESP tuning rather than octaves and semitones.
- `OBS-SR2-GLOB-017` `OBSERVED` (UG p.321, "Locking the Tuning Configuration"): A lock button makes Serum ignore both the TUN file and the concert-pitch setting stored in any newly loaded preset.
- `OBS-SR2-GLOB-018` `OBSERVED` (UG p.325, Appendix A MPE section): In the VST3 build only — explicitly not AU or AAX — disabling MPE makes Serum respond to VST3 Note Expression when the host supports it, with Bitwig, Cubase, and Nuendo named. In that path the note-expression-to-macro mappings remain available but the MPE Bend Range option does not, because VST3 pitch note expression has a fixed range of ±120 semitones.
- `OBS-SR2-GLOB-019` `OBSERVED` (UG pp.325–326, Appendix A): MPE axis mappings are exposed as discrete menu commands: `MPE: XYZ -> Macro 1,2,3`, `MPE: YZ -> Macro 1,2`, and `MPE: Y -> Mod Wheel`. `MPE Bend Range` is settable from 1 to 96 semitones and displayed with its current value in the menu label (48 in the printed example).

## 1.13 Persistence, file structure, and preferences file

- `OBS-SR2-FILE-001` `OBSERVED` (UG p.344, Appendix D): The Serum Presets folder holds every file Serum reads and writes except the preferences file. Default install locations are `/Library/Audio/Presets/Xfer Records/` on macOS and `/Documents/Xfer/` on Windows.
- `OBS-SR2-FILE-002` `OBSERVED` (UG pp.344–345, Appendix D folder table): Named folders and their contents are: Arp Banks (factory and user arp banks), Clip Banks (factory and user clip banks), Multisamples, LFO Shapes, Presets, Samples (tonal and non-tonal), System, Tables.
- `OBS-SR2-FILE-003` `OBSERVED` (UG p.345, Appendix D): LFO shapes are `.XferShape` files in the same format as those used by the LFOTool plug-in, and the same shape files serve three surfaces: the LFO section, the FX waveshaper when the X-Shaper effect type shows its graph, and the Remap editor when a WARP mode is set to Remap.
- `OBS-SR2-FILE-004` `OBSERVED` (UG p.345, Appendix D): The System folder holds four formula text files — `FormulaFactoryMultis`, `FormulaFactorySingles`, `FormulaUserMultis`, `FormulaUserSingles` — all user-editable, with the stated recommendation to edit only the User files. It also holds a `MIDIccMaps` folder for saved MIDI CC maps and `User.dat` holding registration information.
- `OBS-SR2-FILE-005` `OBSERVED` (UG p.345, Appendix D): Wavetables are described as specially saved WAV files in the Tables folder. User subfolders are supported one level deep only — Serum does not scan sub-subfolders. This is a documented, deliberate depth limit on library scanning.
- `OBS-SR2-FILE-006` `OBSERVED` (UG p.340, Appendix C): Application preferences live in `Serum2Prefs.json` at `~/Library/Preferences/` on macOS and `%APPDATA%\Xfer\Serum 2\` on Windows. It stores the Preferences-page settings, the last known path to the Serum Presets folder, and optional power-user options. Serum recreates the file if missing, so deleting it and restarting is the documented factory reset for preferences.
- `OBS-SR2-FILE-007` `OBSERVED` (UG pp.340–343, Appendix C): Documented power-user keys are `"Default Author"` (the artist name stamped on new Init presets), `"Enable CCForRockers"` (0 = off, 1 = MIDI CC stepping, 2 = MIDI note stepping), and paired `+`/`-` keys for preset stepping and for OSC A/B/C and OSC N preset stepping, where `-1` means unassigned.
- `OBS-SR2-FILE-008` `OBSERVED` (UG p.341, Appendix C callout): For CC-driven preset stepping, a received value of 64 or above triggers the action and Serum requires a subsequent value below 64 before the action can fire again. This is a documented hysteresis/edge-trigger rule on an incoming controller.
- `OBS-SR2-FILE-009` `OBSERVED` (UG p.324, Appendix A): `Save as Default Preset` writes to `Serum 2 Presets/Presets/User/default.SerumPreset`, and the Serum FX build writes `defaultFX.SerumPreset` instead. Serum FX looks for `defaultFX.SerumPreset` first and falls back to `default.SerumPreset` — an explicit two-step lookup with a documented fallback.
- `OBS-SR2-FILE-010` `OBSERVED` (UG p.324, Appendix A): `Rescan Folders on Disk` exists specifically because folder changes made outside Serum (in Finder or Explorer) are not detected automatically. The library index is therefore not filesystem-watched.
- `OBS-SR2-FILE-011` `OBSERVED` (UG p.324, Appendix A): Two documented render commands write derived content back into the patch: `Render OSC Warp` takes the selected oscillator's current wavetable frame and generates 256 frames spanning 0–100% of the WARP knob; `Resample to` plays one bar of the preset and captures the result as a wavetable in the selected oscillator (or into OSC A and OSC B).
- `OBS-SR2-FILE-012` `OBSERVED` (UG p.23, "Dragging Audio to Your DAW"): Dragging audio out of Serum to a host track also writes the exported audio as a WAV file into a `Renders` folder under Serum Presets. Option/Alt-clicking the wave icon opens that folder; Shift-dragging the wave icon copies the currently saved preset to Finder/Explorer.
- `OBS-SR2-FILE-013` `OBSERVED` (UG p.324, Appendix A): `Revert to Saved` restores the saved state of the currently loaded preset after edits — a preset-scoped discard distinct from undo.

## 1.14 Undo, tooltips, and control interaction

- `OBS-SR2-UI-001` `OBSERVED` (UG p.27, "Undo and Redo"): Undo and redo are exposed as two buttons in the header near the top right and are described as covering just about any operation, with knob changes and LFO shape edits given as examples. No depth, transaction model, or host-undo integration is stated.
- `OBS-SR2-UI-002` `OBSERVED` (UG p.24, "Displaying Help (Tooltips)"): Tooltips appear on hover-and-pause, are enabled by default on first install, and are gated by the global `Help tooltips` preference. Hovering a control that has modulation assigned lists its modulation sources instead of the ordinary tooltip.
- `OBS-SR2-UI-003` `OBSERVED` (UG p.25, "Using Knobs and Sliders"): Knob interaction is: click-drag vertically or horizontally with a value pop-up; Shift to fine-tune; scroll wheel adjusts without showing the pop-up; double-click opens a numeric entry box — with the double-click behavior switchable to "reset to default" via the global preference.
- `OBS-SR2-UI-004` `OBSERVED` (UG p.26): `Reset Control` and `Lock Parameter` appear on the context menu of almost every control. Lock Parameter prevents preset loading from changing that control while still allowing manual adjustment.
- `OBS-SR2-UI-005` `OBSERVED` (UG p.26): MIDI Learn is per-control: Serum waits for one incoming CC, assigns it, and exits learn mode automatically. The assignment is saved with the preset.

## 1.15 Documented keyboard shortcut families (Appendix G)

- `OBS-SR2-BIND-001` `OBSERVED` (UG pp.349–353, Appendix G): The appendix organises shortcuts into twelve categories: Presets and Presets Browser; Controls (Knobs and Sliders); Modules (Oscillators and Filters); Sample/Granular/Spectral; Audio; FX; Matrix; LFOs; Modulation; Clips; Clips (Note Movements); Clips (Note Operations); Wavetable Editor.
- `OBS-SR2-BIND-002` `OBSERVED` (UG p.349, Presets browser table): Browser bindings are Cmd/Ctrl-F to focus search (documented as working only when already in the browser), Up/Down to step presets, Right to play the preview, Left to stop the preview, Shift-click to multi-select, Shift-Backspace to delete selected presets, and Option/Alt-click the save button to save under the same name without a dialog.
- `OBS-SR2-BIND-003` `OBSERVED` (UG p.349, Controls table): Two universal control bindings exist: Shift-drag fine-tunes, Cmd/Ctrl-click resets.
- `OBS-SR2-BIND-004` `OBSERVED` (UG p.350, Sample/Granular/Spectral table): In sample-family oscillators, Option/Alt-click adds a slice manually, Option/Alt-click on an existing slice removes it, and Option/Alt-click-and-drag the button changes the granular window amount and skew.
- `OBS-SR2-BIND-005` `OBSERVED` (UG pp.350–351): Option-F / Alt-F is reused as an expand/revert toggle in two distinct contexts — the FX rack and list view, and the modulation matrix view. Cmd/Ctrl-U is reused as Chop in the clip piano roll while it is also the documented `Limit`-adjacent shortcut namespace elsewhere; the guide's own tables show no conflict because contexts do not overlap.
- `OBS-SR2-BIND-006` `OBSERVED` (UG p.351, Modulation table): Shift-Option/Shift-Alt-click on a modulated control toggles that modulation between directional and bidirectional.
- `OBS-SR2-BIND-007` `OBSERVED` (UG p.353, Wavetable Editor table): Wavetable Editor bindings are click-drag to move a frame, Shift-click to select a range of frames, and Shift-Cmd/Shift-Ctrl-click to shift the phase offset to the right.
- `OBS-SR2-BIND-008` `OBSERVED` (UG pp.349–353, whole appendix): The modifier grammar is consistent across every category — Shift = fine/extend/multi-select, Option/Alt = alternate scope, snapping, or "apply to all", Cmd/Ctrl = reset or relative/marquee selection, and Shift+Option/Alt = the "with modulations" variant of a copy.

## 1.16 Change-guide-only observations (What's New PDF)

The change guide is an annotated screenshot document whose text is short callout labels. Its claims are coarse-grained feature statements, not full semantics, and where the user guide covers the same ground the user guide is the stronger source. Records here are limited to statements the guide asserts about **differences from Serum 1** or about counts the user guide sections inspected did not restate.

- `OBS-SR2-WN-001` `OBSERVED` (WN p.4, "Expanded Oscillators"): Serum 2 has three primary oscillators against two in Serum 1, and retains a dedicated sub oscillator and a dedicated noise oscillator described as similar to and as in Serum 1 respectively.
- `OBS-SR2-WN-002` `OBSERVED` (WN pp.5–6, "New Oscillator Modes"): Five oscillator modes are named: Wavetable, Multisample, Sample, Granular, Spectral. Spectral is described as analysing and resynthesising the frequency spectrum with independent control over time and pitch.
- `OBS-SR2-WN-003` `OBSERVED` (WN p.6, "Wavetable Enhancements"): Callouts name four wavetable tuning modes (semitone, harmonics, ratio, step), copy/paste of oscillators with or without modulations, phase memory, a smooth wavetable-position interpolation option described as giving table transitions without morph tables, additional warp modes including true FM and PD from filters, and dual warp (two warp modes at once). All are corroborated in the user guide.
- `OBS-SR2-WN-004` `OBSERVED` (WN p.8, "More New Oscillator Highlights"): Granular playback is stated as supporting up to 256 grains, and the Multisample oscillator is stated to support loading SFZ files. Neither figure nor format was restated in the user guide pages inspected for this pass.
- `OBS-SR2-WN-005` `OBSERVED` (WN p.7, "Sample Mode Highlights"): Forward-reverse looping tails for real-time stretching are named, with an explicit note that they are also available in Granular and Spectral modes.
- `OBS-SR2-WN-006` `OBSERVED` (WN p.12, "New Signal Splitter Modules"): The three splitters are labelled Splitter L/H (lows/highs), Splitter L/M/H (lows/mids/highs), and Splitter M/S, whose caption reads "Mid/Slide". The user guide's contents list the third as "Splitter MS" (UG p.180). The change guide's caption is recorded as printed.
- `OBS-SR2-WN-007` `OBSERVED` (WN p.11, "New and Enhanced FX"): Newly named or changed effects are Bode (a frequency shifter), Convolve (a convolution effect), Delay (a new HQ mode described as now the default), Distortion (a new Overdrive mode and a DC bias control), Reverb (three new types: Vintage, Nitrous, Basin), and Utility.

# Part 4 — Cross-cutting patterns

Every item here is `SPECTRE-CANDIDATE`. None carries authority; none is adopted; each is a question for the requirements ledger, not an answer.

1. `SPECTRE-CANDIDATE` — **Module scope is the unit of lock, init, copy, and clipboard.** Lock Module, Init Module, Copy / Copy (w/mods), Lock FX Bus, Lock Matrix, Lock Parameter, and quality/tuning locks all express the same idea at different granularities: "hold this piece steady while the rest changes." Spectre's device model needs an explicit answer for what the lockable unit is, and whether locking preserves modulation (Serum's FX bus lock notably does not — `OBS-SR2-FX-008`).
2. `SPECTRE-CANDIDATE` — **Copy semantics are consistently two-tier: with or without modulations.** Oscillators, filters, FX modules, and LFO tabs all use the same Option/Alt versus Shift-Option/Alt split, and the unmodified drag means swap rather than copy. A single, uniform "structure versus structure-plus-wiring" rule is cheaper to teach than per-surface rules.
3. `SPECTRE-CANDIDATE` — **Voice accounting is not one-voice-per-note.** Unison count and granular grain count both enter the voice total (`OBS-SR2-VOICE-007`), and the polyphony readout's denominator is derived from patch content rather than the POLY setting. Spectre's voice budget contract should define what a voice *is* before it defines how many there are.
4. `SPECTRE-CANDIDATE` — **Voice stealing is published product behavior with a five-way policy, not implementation folklore.** Together with Phase Plant's oldest-and-quietest rule already on record in `synth-modular-observations.md`, that is two flagship instruments treating steal priority as a user-visible choice.
5. `SPECTRE-CANDIDATE` — **Phase and retrigger policy is where legato semantics actually live.** Serum documents three separate, interacting switches — global LEGATO, per-envelope Legato Inverted, and per-oscillator Phase Legato (`OBS-SR2-VOICE-002`, `-004`, `-011`) — because one global toggle cannot express the needed cases. A single legato flag is likely to be under-specified.
6. `SPECTRE-CANDIDATE` — **Modulation depth is contextual at assignment time.** Polarity is inferred from control geometry (`OBS-SR2-MOD-006`) and depth can be auto-limited against headroom (`OBS-SR2-MOD-007`). Both are attempts to make the common case correct without a dialog, and both create surprise when the inference is wrong — the exact friction a practitioner reports in `WF-SR2-LFOARP-001d`.
7. `SPECTRE-CANDIDATE` — **A modulation source list can itself be tiered by reachability.** Serum has sources that only exist in the matrix (`OBS-SR2-MOD-010`) because they have no sensible drag gesture. Spectre needs a deliberate answer for whether every source is draggable, or whether some are matrix-only by design.
8. `SPECTRE-CANDIDATE` — **In-instrument sequencing duplicates host concepts and therefore duplicates their contracts.** The CLIP module independently reimplements launch quantisation, retrigger-versus-sync, velocity scaling, note-gate, scale conformance, grid, fold, marquee zoom, and a two-state record-commit model. For a sequencer product, the question is not whether to build this but where the boundary between instrument-local and project-level sequencing sits.
9. `SPECTRE-CANDIDATE` — **The same 12-slot, bank, EDIT ALL, Option-to-broadcast, asterisk-on-modified, save-defaults-to-new-name pattern is reused verbatim across CLIP and ARP.** Deliberate structural reuse across two modules is cheap consistency; Spectre should decide its equivalent pattern once.
10. `SPECTRE-CANDIDATE` — **Two independent gates guard key-command dispatch** (`OBS-SR2-CLIP-014`): a global "does this plug-in take keyboard input at all" preference that exists to protect host focus, and per-pane keyboard focus with a visible focus indicator. Any embedded editor inside a host needs both, and needs to show the user which one is blocking.
11. `SPECTRE-CANDIDATE` — **Derived content is written to disk as new files rather than mutating sources** — Renders for dragged audio, resample-to-wavetable, render-warp-to-256-frames. This matches Ableton's `Samples/Processed/<Operation>` convention already on record. A non-destructive-by-default file policy appears to be the industry norm rather than a differentiator.
12. `SPECTRE-CANDIDATE` — **Library indexing is explicitly not filesystem-watched and explicitly one level deep** (`OBS-SR2-FILE-005`, `-010`). Both are limits a mature product chose to publish rather than hide. Spectre should decide its scan depth and freshness policy explicitly and document it.
13. `SPECTRE-CANDIDATE` — **Compatibility with a predecessor is modelled as per-preset DSP state with an automatic trigger** (`OBS-SR2-GLOB-010`), not as a global legacy mode. If Spectre ever ships a v2 engine, this is a demonstrated pattern for not breaking existing sounds.
14. `SPECTRE-CANDIDATE` — **Tuning has a published precedence order** (`.tun` file beats MTS-ESP; lock beats preset — `OBS-SR2-GLOB-016`, `-017`). Precedence between competing sources of truth is exactly the kind of rule that must be written down before implementation rather than discovered from bug reports.
